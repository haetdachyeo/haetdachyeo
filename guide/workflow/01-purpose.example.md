# 프로젝트 목적과 설명

## 목적

이 프로젝트가 무엇을 달성하려는지 첫 문장에 작성한다. 배경보다 결론을 먼저 제시하고, 이 문장만 읽어도 프로젝트의 목적을 알 수 있도록 한다.

- 무엇을 만드는가?
- 그것을 통해 무엇을 달성하려는가?

## 배경과 문제

이 프로젝트가 필요해진 이유와 해결하려는 문제를 작성한다.

- 현재 사용자는 어떤 문제를 겪고 있는가?
- 기존에는 어떻게 해결하고 있으며, 그 방식의 한계는 무엇인가?
- 왜 이 프로젝트가 필요한가?

## 대상 사용자

누가 어떤 상황에서 이 프로젝트를 사용하는지 작성한다. 사용자 유형이 여러 개라면 구분한다.

- 주요 사용자는 누구인가?
- 어떤 상황에서, 어떤 필요 때문에 사용하는가?

## 예상 사용 규모

프로젝트를 만들 때 어느 정도의 사용자가 이용할 것으로 예상하는지 정한다. 이 예상 규모를 아키텍처와 코드 구성을 결정하는 설계 전제로 사용한다. 작성자가 예상 인원을 정하고, 어느 시기의 이용 규모를 가정했는지 함께 적는다.

- 어느 시기의 이용 규모를 예상하는가?
- 해당 시기에 전체 사용자는 몇 명일 것으로 예상하는가?
- 그중 같은 시간에 사용하는 사용자는 몇 명일 것으로 예상하는가?

## 사용자에게 주는 가치

사용자가 이 프로젝트를 사용하면 무엇이 나아지는지 작성한다. 기능을 나열하기보다 사용자가 얻는 변화를 설명한다.

- 기존 방식과 비교해 무엇이 나아지는가?
- 사용자의 어떤 불편이나 부담이 줄어드는가?

## 성공 기준

어떤 결과를 얻으면 프로젝트의 목적을 달성했다고 판단할지 작성한다. 각 기준에는 확인 방법과 판단 시점을 함께 적는다.

- 무엇을 확인하면 사용자에게 의도한 가치를 제공했다고 볼 수 있는가?
- 언제, 어떤 방법으로 달성 여부를 판단하는가?
