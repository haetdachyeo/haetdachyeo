# 블로그 서비스의 기술과 아키텍처

## 설계 방향

블로그 예시 설계안: **모듈형 모놀리스**, 애플리케이션 1개·관계형 DB 1개. 계정·글 관리 모듈을 구분하되 단일 프로그램으로 배포.

| 항목 | 전제·목표 |
| --- | --- |
| 예상 규모 | 첫 배포 후 3개월, 전체 1,000명·동시 50명 |
| 성능 검증 | 동시 사용자 100명, 동작별 성공 건 p95 2초 이하 |
| 월간 가용성 | 동작별 99.5% 이상 |
| 운영 구성 | 단일 지역, 개별 서비스 배포·관리 없음 |
| 변경 반영 | 글 작성·수정·삭제 완료 후 조회에 반영 |

배포·요청 처리 단순화. 별도 캐시·메시지 브로커·검색 서버 미도입.

## 시스템 구성 요약

```text
클라이언트
    |
    | HTTPS
    v
블로그 애플리케이션
    |
    | SQL
    v
PostgreSQL
```

| 구성요소 | 책임 |
| --- | --- |
| 클라이언트 | 회원가입·로그인·글 작성·조회·수정·삭제 요청, 결과 표시. 화면·클라이언트 기술은 별도 |
| 애플리케이션 | HTTPS 수신·입력 검증·회원 식별·권한 확인·계정 및 글 관리·응답 생성 |
| PostgreSQL | 회원·세션·글의 기준 저장소. 조회·변경에 동일 DB 사용 |

내부 책임: HTTP 요청·응답 / 계정·인증 / 글 관리 / 데이터 접근.
계정·인증은 현재 회원 식별, 글 관리는 작성·수정·삭제의 소유권 규칙 담당.

- **쓰기**: 변경 완료 후 성공 응답. 실패 시 부분 변경 방지, 트랜잭션 경계 정의.
- **공개 반영**: 별도 비동기 작업으로 지연하지 않음.
- **첫 배포**: Linux 호스트의 Docker, 애플리케이션·DB 컨테이너 각 1개.
- **장애**: 단일 인스턴스 중단 가능. 재시작·복구 절차와 실측 가용성으로 검증. 예상 규모만으로 목표 달성 단정 금지.

## 사용 기술 요약

| 영역 | 기술·버전 | 용도 |
| --- | --- | --- |
| 서버 언어 | Go 1.27.3 | 블로그 구현 |
| HTTP 처리 | Go 1.27.3 표준 `net/http` | HTTPS 수신·API 응답 |
| 데이터베이스 | PostgreSQL 18.6 | 회원·세션·글 영속 저장 |
| 호스트 운영체제 | Linux | Docker 실행 호스트 |
| 서버 실행 환경 | Docker | 애플리케이션·DB 별도 컨테이너 |

- **HTTP**: 별도 웹 프레임워크 없이 표준 기능 사용.
- **저장**: 단일 관계형 DB, 계정 고유성·글 소유권·변경 무결성 관리.
- **로그인**: 서버 세션. 쿠키로 식별자 전달, PostgreSQL 세션의 유효성·회원 확인.

상세화 대상: 세션 수명·쿠키 보안·비밀번호 보호·DB 접근 라이브러리·실행 환경 세부 버전.

상세 설계 주제:

- **제약·운영 기준**: 자원·예산·배포 환경·부하·성능·가용성 검증.
- **기술 선택**: 기술·버전, 선택 이유·대안·트레이드오프.
- **시스템·모듈 경계**: 책임·의존 방향·요청 및 데이터 흐름·트랜잭션·장애 경계.
- **인증·보안**: 비밀번호·세션 발급/만료/폐기·쿠키·권한·HTTPS.
- **저장·운영**: 무결성·동시 변경·마이그레이션·배포·복구·백업·관측.

새 상세 문서 작성 시 경로·읽는 순서 추가. 사양의 기준은 담당 상세 문서, 대표 문서는 전체 구성·주요 선택 요약.
