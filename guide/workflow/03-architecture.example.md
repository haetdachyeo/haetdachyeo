# 기술과 아키텍처

## 설계 방향

프로젝트의 목적, 범위와 예상 사용 규모를 바탕으로 어떤 방향의 시스템을 구성할지 간략하게 작성한다. 기술 선택에 영향을 주는 주요 제약조건이 있다면 함께 요약한다.

- 어떤 구조를 선택하며, 이 프로젝트에 적합한 이유는 무엇인가?
- 예산, 운영 환경, 팀 역량, 성능·보안 조건 중 설계에 영향을 주는 것은 무엇인가?

구체적인 제약조건과 설계 판단의 근거는 해당 상세 문서에서 정의한다.

## 시스템 구성 요약

전체 시스템의 주요 구성요소와 각 역할, 구성요소 사이의 연결 관계를 요약한다. 필요하면 간단한 구성도를 함께 작성한다.

- 시스템은 어떤 구성요소로 이루어지는가?
- 각 구성요소는 무엇을 담당하며 서로 어떻게 연결되는가?

내부 모듈의 책임과 의존 관계, 통신 방식, 데이터 흐름과 장애 경계는 상세 문서에서 구체화한다.

## 사용 기술 요약

선택한 언어, 프레임워크, 저장소와 실행 환경 등 주요 기술을 용도와 함께 간략하게 작성한다.

- 어떤 기술을 어디에 사용하는가?
- 선택한 기술의 버전은 무엇인가?

선택 이유, 검토한 대안, 트레이드오프와 구체적인 적용 방식은 상세 문서에서 정의한다.

## 상세 설계 문서 안내

상세 설계는 이 대표 문서와 같은 위치의 `03-architecture/` 폴더에 주제별로 작성한다. 이 섹션에는 실제로 작성한 상세 문서의 경로와 다루는 내용을 정리한다.

- 어떤 설계 주제를 어떤 문서에서 다루는가?
- 전체 구조를 이해하기 위해 어떤 순서로 읽으면 되는가?

하위 문서 구성은 프로젝트에 필요한 설계 영역에 따라 정한다. 제약조건, 기술 선택, 시스템 구성, 모듈 경계 등 독립적으로 설명해야 할 주제가 있다면 문서를 분리한다.

각 상세 문서에는 해당 주제에 필요한 조건과 규칙, 선택한 설계, 선택 이유, 대안과 트레이드오프, 검증 방법을 구체적으로 작성한다.

각 설계 항목의 기준은 담당 상세 문서 한곳에 둔다. 대표 문서는 요약과 안내 역할을 맡으며, 상세 문서가 변경되면 영향을 받는 요약도 함께 갱신한다.
