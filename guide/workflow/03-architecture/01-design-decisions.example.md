# 설계 전제와 기술 선택

## 설계 전제

작성자가 정하는 예상 이용 조건.

- 예상 시점·전체 사용자·동시 사용자
- 주요 동작·읽기/쓰기 비중
- 평균·최대 요청량·데이터 증가량
- 지원 클라이언트·서비스 지역

요청량·데이터량의 산정 가정 명시. 동시 사용자 수만으로 요청량 단정 금지, 사용자별 요청 빈도 등 포함.

## 제약조건과 품질 목표

고정 제약·선택 가능 사항 구분.

- 서버 자원·월간 운영 예산
- 호스트 OS·컨테이너 환경·배포 지역
- 개발/운영 인원·기술 역량·운영 시간
- 응답시간·가용성 목표
- 허용 중단 시간·데이터 손실 범위
- 보호 데이터·필수 보안 조건

수치별 적용 대상·측정 구간·조건 명시. 예상 이용 규모와 검증 부하 구분. 조건별 기술·구조 선택에 미치는 영향 기록.

## 기술과 구조의 선택

언어·프레임워크·저장소·환경·아키텍처 등 항목별 작성. 기술 나열보다 현재 조건에 대한 적합성 중심.

### 선택 항목 이름

- **필요**: 해결할 문제.
- **선택**: 기술·버전·용도·주요 구성, 책임 통합/분리 범위.
- **조건**: 판단 근거가 된 설계 전제·제약·품질 목표.
- **이유**: 조건을 만족하는 근거.
- **대안**: 검토한 방식·제외 이유.
- **트레이드오프**: 이득·비용·제한·운영 부담.

미도입 결정도 기록 가능. 특정 언어·구조를 정답으로 전제하지 않고 프로젝트 조건으로 판단.

## 검증 및 재검토 기준

선택의 적합성 판정 조건 명시. 상세 실행 절차는 담당 설계에서 구체화.

- 성능 검증 환경·부하·통과 기준
- 자원 사용·비용·장애 복구 판정 기준
- 규모·품질·운영 조건 변경 시 재검토 기준
- 검증 미달 항목별 재검토 대상

계획·실측 결과 구분. 선택 변경 시 해당 항목 직접 수정, 대표 문서 요약 동기화.
