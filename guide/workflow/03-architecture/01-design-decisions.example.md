# 설계 전제와 기술 선택

## 설계 전제

이 아키텍처가 어떤 이용 상황을 예상하고 설계되는지 작성한다. 예상 사용 규모를 요청량이나 데이터 규모로 해석할 때는 어떤 가정을 사용했는지 함께 적는다.

- 어느 시점의 전체 사용자 수와 동시 사용자 수를 기준으로 설계하는가?
- 사용자가 주로 수행하는 동작은 무엇이며, 읽기와 쓰기의 비중은 어느 정도인가?
- 평균·최대 요청량과 데이터 증가량을 어느 정도로 예상하는가?
- 지원할 클라이언트와 서비스 지역은 어디인가?

예상 수치는 작성자가 정하는 설계 전제다. 동시 사용자 수만으로 초당 요청량을 단정하지 않고, 사용자별 요청 빈도 등 필요한 가정을 명시한다.

## 제약조건과 품질 목표

기술과 구조의 선택에 영향을 주는 조건을 작성한다. 이미 정해진 제약과 이번 설계에서 선택할 수 있는 사항을 구분한다.

- 서버 자원과 월간 운영 예산은 어느 정도인가?
- 호스트 운영체제, 컨테이너 실행 환경, 배포 지역 등 이미 정해진 환경이 있는가?
- 개발·운영 인원과 기술 역량, 운영에 사용할 수 있는 시간은 어느 정도인가?
- 응답시간과 가용성은 어느 수준을 목표로 하는가?
- 허용할 수 있는 서비스 중단 시간과 데이터 손실 범위는 어느 정도인가?
- 개인정보나 인증정보 등 보호해야 할 데이터와 반드시 지켜야 할 보안 조건은 무엇인가?

수치 목표에는 적용 대상, 측정 구간과 조건을 함께 작성한다. 예상 이용 규모와 성능 검증용 부하 조건이 다르면 각각 구분한다. 각 조건이 어떤 기술이나 구조의 선택을 제한하는지도 설명한다.

## 기술과 구조의 선택

언어, 프레임워크, 저장소, 실행 환경과 전체 아키텍처 등 결과에 영향을 주는 선택을 항목별로 작성한다. 기술 이름을 나열하는 데 그치지 않고, 현재 조건에서 그 선택이 적합한 이유를 설명한다.

선택할 항목마다 아래 구조를 반복한다.

### 선택 항목 이름

- **문제와 필요**: 어떤 문제를 해결하기 위한 선택인가?
- **선택 내용과 적용 범위**: 무엇을 어디에 사용하는가? 기술의 버전과 함께 사용할 주요 구성은 무엇인가? 구조를 선택한다면 어떤 책임을 묶거나 분리하는가?
- **판단 조건**: 어떤 설계 전제, 제약조건과 품질 목표를 근거로 판단했는가?
- **선택 이유**: 선택한 방식이 현재 조건을 어떻게 만족하는가?
- **검토한 대안**: 다른 가능한 방식은 무엇이며, 왜 선택하지 않았는가?
- **트레이드오프**: 무엇을 얻고, 어떤 비용·제한·운영 부담을 받아들이는가?

기술 선택의 범위에는 별도로 도입하지 않기로 한 구성요소도 포함할 수 있다. 특정 언어나 아키텍처를 정답으로 전제하지 않고 프로젝트의 조건을 근거로 결정한다.

## 검증 및 재검토 기준

선택한 기술과 구조가 설계 전제를 만족하는지 어떻게 확인할지 작성한다. 상세 실행 절차를 다른 설계 주제에서 다루더라도, 여기서는 선택의 적합성을 판단할 조건을 명확하게 정한다.

- 어떤 환경과 부하에서 성능 목표의 충족 여부를 확인하는가?
- 자원 사용량, 운영 비용과 장애 복구 결과를 어떤 기준으로 판단하는가?
- 예상 사용 규모, 품질 목표나 운영 조건이 어떻게 달라지면 선택을 재검토하는가?
- 검증 결과가 기준에 미달하면 어떤 선택을 다시 검토해야 하는가?

검증 계획과 실제 확인 결과는 구분한다. 선택을 변경하면 이 문서의 해당 항목을 현재 결정으로 갱신하고, 영향을 받는 대표 문서의 요약도 함께 맞춘다.
